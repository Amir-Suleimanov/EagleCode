# Аудит работы EagleCode

Дата: 2026-09-26. Проверено на живом стенде: PostgreSQL 16 + Django API (`127.0.0.1:8000`)
+ Vite dev server (`localhost:5173`) с `VITE_DATA_SOURCE=api`, браузер Chromium.

Объём проверки:

- 23 маршрута открыты в реальном браузере под ролями «аноним», «спортсмен», «администратор»;
- 55 HTTP-проверок API (регистрация → заявка → модерация → результат → метры → журнал → уведомления → права → токены);
- пользовательские сценарии через UI: вход, регистрация, заявка, модерация, публикация результата, начисление метров, правка уровней, выход;
- мобильный вьюпорт 390 px, консоль браузера, сетевые ответы.

Статус: **2 блокирующие ошибки, 3 серьёзные, 3 средние, 3 низкие.**
**Все исправлены.** Плюс E12, найденная в ходе работы над E1.

### E12. Email спортсменов был бы виден анонимам

**Статус: исправлено.**

Обнаружено при исправлении E1: открытие `/api/athletes` для анонимного чтения отдавало бы
поле `email` каждого участника — утечка персональных данных. `AthleteSerializer` теперь
отдаёт `email` только самому спортсмену и администратору; в публичном реестре поля нет.
Покрыто тестом `test_public_roster_hides_emails`.

Проверено после исправлений: все 23 маршрута открываются без ошибок консоли и сети,
регистрация проходит end-to-end (5 городов в списке → профиль создан), главная отрисовывает
все секции и якоря публичной шапки.

## Блокирующие

### E1. Публичная главная `/` никогда не загружается

**Статус: исправлено.**

**Симптом.** Аноним видит только спиннер «Загрузка данных…» — бесконечно. Контента нет
вообще; в подвале при этом написано «Все системы работают».

**Причина.** Два слоя:

1. Backend: `REST_FRAMEWORK.DEFAULT_PERMISSION_CLASSES = ["IsAuthenticated"]`
   (`backend/config/settings.py:106`), и публичные вьюхи от него не отписаны. Анонимные
   запросы `/api/athletes`, `/api/cities`, `/api/competitions` возвращают **401**.
2. Frontend: `HomePage` (`src/pages/public/HomePage.tsx:14`) рендерит
   `if (!athletes.data || !cities.data || !competitions.data) return <LoadingState />`.
   Ветки ошибки нет, поэтому 401 превращается в вечный спиннер.

**Последствия.** Неработающая витрина продукта плюс четыре ссылки в публичной шапке
(`/#levels`, `/#rating`, `/#competitions`, `/#cities` — `PublicLayout.tsx:15`) ведут в
никуда, так как секции-якоря не отрисовываются.

**Проверка.** `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8000/api/cities` → `401`.

### E2. Зарегистрироваться невозможно

**Статус: исправлено.**

**Симптом.** На `/register` поле «Населённый пункт» — пустой `<select>` с нулём вариантов.
Поле обязательное (`required`), поэтому форма не отправляется. Новый пользователь
физически не может завести профиль.

**Причина.** Та же, что в E1: `GET /api/cities` → 401 для анонима. В разметке
`cities.data?.map(...)` (`src/pages/public/AuthPages.tsx:36`) — опциональная цепочка гасит
ошибку, страница рисуется, но список городов пуст.

**Проверка.** В браузере на `/register`: `document.querySelector('select').options.length === 0`.

## Серьёзные

### E3. Ни одна страница с данными не обрабатывает ошибки API

**Статус: исправлено.**

**Симптом.** Любой сбой запроса (401, 500, обрыв сети) показывает вечный спиннер. Нет ни
сообщения, ни кнопки повтора; пользователь не понимает, что произошло.

**Охват — все 16 страниц:** `HomePage`, `ProfilePage`, `RatingPage`, `CompetitionsPage`,
`CompetitionDetailPage`, `ResultsPage`, `AchievementsPage`, `LevelsPage`, `MapPages`,
`AdminDashboardPage`, `AdminUsersPage`, `AdminCompetitionsPage`, `AdminApplicationsPage`,
`AdminResultsPage`, `AdminRatingPage`, `AdminLevelsPage`.

**Причина.** Общий шаблон `if (!query.data) return <LoadingState/>` — состояние
`query.isError` не используется нигде.

### E4. Уведомления реализованы, но не подключены к интерфейсу

**Статус: исправлено.** Колокольчик открывает панель уведомлений (drawer): список с иконкой,
текстом и временем, отметка «Прочитано» поштучно и «Отметить все прочитанными», точка горит
только при наличии непрочитанных. Работает и против API, и в mock-режиме.

**Симптом.** Колокольчик в шапке (`DashboardLayout.tsx:45`) — кнопка без `onClick`. Рядом
постоянно горит красная точка `notification-dot`, не связанная с реальными непрочитанными.

**Причина.** Backend создаёт уведомления при каждом решении по заявке и начислении метров,
`DataClient` объявляет `getNotifications` и `markNotificationRead`, `HttpDataClient` их
реализует — но **ни один компонент их не вызывает**. Функциональность недоступна
пользователю целиком.

**Проверка.** `grep -rn "getNotifications" src` даёт совпадения только в слое сервисов.

### E5. Таблица рейтинга игнорирует уровни из API

**Статус: исправлено.**

**Симптом.** Администратор меняет порог уровня на `/admin/levels`, изменение сохраняется в
БД, но таблица рейтинга продолжает показывать прежние уровни.

**Причина.** `RankingTable` (`src/components/features/RankingTable.tsx:15`) вычисляет уровень
из захардкоженной константы `eagleLevels`, а не из данных `/api/levels`. Пропса `levels`
у компонента нет.

## Средние

### E6. Поиск в шапке ничего не делает

**Статус: исправлено.** Поле стало формой: запрос уходит в реестр участников
(`/app/rating?q=…` для спортсмена, `/admin/users?q=…` для администратора), а страницы читают
`q` из URL в существующий фильтр. Результат поиска можно передать ссылкой.

`DashboardLayout.tsx:44` — `<input>` без значения, состояния и обработчика. Элемент выглядит
рабочим, но не ищет.

### E7. Хлебные крошки не отражают текущую страницу

**Статус: исправлено.**

`DashboardLayout.tsx:42` — подпись жёстко задана ролью: «Спортивный профиль» для спортсмена,
«Центр управления» для администратора. На всех 8 страницах спортсмена в шапке написано
«Спортивный профиль», даже когда открыты «Соревнования» или «Карта».

### E8. `MockDataClient` не соответствует контракту `DataClient`

**Статус: исправлено.** Mock хранит уведомления вместе с получателем, отдаёт только записи
текущего пользователя (новые сверху), отмечает прочитанными и сам создаёт их при решении по
заявке и при начислении метров — как это делает backend. Покрыто четырьмя тестами.

`getNotifications` всегда возвращает `[]`, `markNotificationRead` всегда бросает исключение
(`MockDataClient.ts:149-150`). Демо-режим без backend не воспроизводит поведение API.

## Низкие

### E9. README противоречит сам себе в настройке API

**Статус: исправлено.** В обоих местах указан абсолютный `http://localhost:8000/api`
с пояснением, почему относительный путь не сработает.

В разделе «Для подключения backend» указано `VITE_API_BASE_URL=/api`, но в `vite.config.ts`
нет прокси — такой запрос уйдёт на dev-сервер и вернёт 404. Ниже в том же файле указано
корректное `http://localhost:8000/api`.

### E10. CORS настроен только на `localhost:5173`

**Статус: исправлено.** По умолчанию разрешены оба написания dev-сервера,
`localhost:5173` и `127.0.0.1:5173`; то же в `.env.example`.

Открытие того же приложения по `127.0.0.1:5173` ломает все запросы (preflight без
`Access-Control-Allow-Origin`). Для браузера это разные origin. Стоит перечислить оба.

### E11. `pip install -e '.[dev]'` из `backend/README.md` падает

**Статус: исправлено.** В `pyproject.toml` пакеты перечислены явно
(`[tool.setuptools] packages = ["apps", "common", "config"]`), установка проходит.

setuptools не может определить пакеты: `Multiple top-level packages discovered in a
flat-layout: ['apps', 'config', 'common']`. Документированная команда установки не работает.

## Что проверено и работает

Чтобы отделить сломанное от исправного:

- вход спортсменом и администратором, сообщение об ошибке при неверном пароле, выход с
  полной очисткой `localStorage`;
- все 16 авторизованных страниц открываются без ошибок консоли и сети;
- маршрутные guard'ы: аноним уходит на `/login`, спортсмен с `/admin` — на `/app/profile`;
- админские действия: одобрение заявки, форма создания соревнования (9 полей), диалог
  начисления метров, правка порогов уровней (10 полей) — все завершаются без ошибок;
- бизнес-правила API: повторная заявка, решение по уже решённой заявке, результат без
  одобренной заявки, нулевые и уводящие баланс в минус метры, пороги уровней вне соседних
  значений — все корректно отклоняются;
- изоляция данных: спортсмен видит только свой журнал метров, чужие достижения закрыты;
- `seed_demo` идемпотентен, миграции синхронны, схема OpenAPI генерируется без предупреждений;
- мобильный вьюпорт 390 px: горизонтального переполнения нет ни на одной проверенной странице;
- маршрут `/api/health` ходит в БД и отвечает `200`.
